# Google Flow naming and import

## Research finding

Google Flow Agent can be asked to rename selected assets. Its help also documents
project collections and downloading projects. The docs do not promise that a
custom prompt prefix becomes the downloaded filename. Google Takeout exports
media under internal IDs and pairs each file with metadata JSON.

Sources (checked 15 Nov 2026):

- [Use the Google Flow Agent](https://support.google.com/flow/answer/17093911)
- [Manage Flow projects and assets](https://support.google.com/flow/answer/16935308)
- [Download Google Flow data](https://support.google.com/labs/answer/17571126)

## Recommended operator pattern

Use a per-request instruction like: “Generate one image for request
`story_<key>`. After generation, rename the Flow asset to
`story_<key>_<short-scene-slug>` and place it in the matching request
collection. If you cannot rename it, report that and leave the asset unchanged.”

1. Keep the workbench `story_key` in the prompt and ask the Agent to rename the
   generated asset to `story_<key>_<short-scene-slug>`.
2. Ask the Agent to put outputs in a collection named for the request or batch.
3. Verify the Flow asset title after generation; treat naming as best-effort.
4. On download/import, retain Flow's metadata JSON when available and map it to
   the workbench request. Do not trust filename alone to route an image.
5. If the downloaded name is an internal ID, generate a local safe filename
   from the validated request key during intake; preserve the original ID as
   `source_media_id` in metadata.

## Stable identifiers

- `story_key`: intended story beat, generated by our story scanner.
- `asset_id`: actual image bytes, generated by our importer.
- Flow `media_id`: Flow export identity, when present.
- Ren'Py alias: code-facing image name created after review.

These IDs are different and must not be substituted for each other.
